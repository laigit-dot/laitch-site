Laitch

Privacy policy

Last updated: November 24, 2026

Summary

Laitch is a desktop application that runs on the user's own Windows computer. It has no servers and no account system of its own. Data it reads from Google stays on that computer.

What Laitch accesses

When the user connects a Google account, Laitch requests one permission:

  • Gmail, read-only (gmail.readonly): to read recent messages and find a verification code or confirmation link that a job site sent while the user is applying there. Laitch also reads the mailbox's own address from its Gmail profile, so it uses the mailbox whose address matches the one used on the application.

Laitch cannot send, delete, move, label or otherwise change email.

How the data is used

  • Messages are read only while an application is waiting on a verification email, and only messages that arrived around that time.
  • The code or link found in a message is entered on the job site that sent it. Nothing else from the message is used.
  • Message content is processed on the user's computer. It is not sent to the developer, to any server, to any AI or analytics service, or to any other third party, and it is not used for advertising.
  • Message content is held in memory only while it is checked and is never written to disk; Laitch's log records only that a verification email was found, not what it says.

Storage and security

The sign-in tokens Google issues are stored only on the user's computer, encrypted with Windows Data Protection for that Windows user. No copy is kept anywhere else.

Removing access

Choosing Disconnect next to the account in Laitch's Settings, under Email accounts, deletes its stored tokens. Access can also be revoked at any time at myaccount.google.com/permissions.

Google API Services User Data Policy

Laitch's use and transfer of information received from Google APIs adheres to the Google API Services User Data Policy, including the Limited Use requirements.
